## ⚠️ EXP-503 has NO faithful backtest twin — this is a CORE-ONLY run

The deployed EXP-503 ("ML V2 Aggressive", `configs/paper_exp503.yaml`) is CreditSpreadStrategy wrapped in the ML V2 overlay. That overlay is **not representable in the backtester**, and this run deliberately omits it. What's missing, specifically:

1. **The ML overlay itself** (`strategies/ml_enhanced_strategy.py` + RegimeModelRouter): per-regime size multipliers 0.00–1.50×, `regime_gate: true` (suppresses signal *generation* in bear/high_vol), a 25 %-weighted pre-trained joblib signal-model confidence blend, and `min_score_threshold: 30` dropping scaled signals. `main.py:139-141` states the ML pipeline is disconnected from the backtest path by design ("Reconnect only after the ML model has been backtested end-to-end" — it never was). The overlay changes the **entry stream**, not just sizing, so its omission is structural.
2. **The registry pointer is dangling and mislabeled:** `experiments/registry.json` lists `backtest_config: configs/exp_503_lowvol_narrow_spread.json` — that file does not exist on disk, has no history in this repo, and per `scripts/run_lowvol_experiments.py` belonged to the EXP-501…520 *low-vol parameter sweep*, a different experiment that reused the EXP-503 number. The deployed ML model has never had a backtest twin of any kind.
3. **`regime_scale_*` risk scaling** (bull 1.0 / bear 0.3 / high_vol 0.3 / low_vol 0.8 / crash 0.0) — no engine support (crypto engine only).
4. **`delta_threshold: 0.30` exit** — not an engine exit rule.

What IS run here: the credit-spread + iron-condor **core** of the yaml (its own header calls it "the EXP-401 core, no ML sizing"): SPY, DTE 15 (15–25), 3 % OTM, $5 width, PT 55 %, SL 1.25×, combo regime (MA200), VIX ≤ 30 entry gate, flat 8.5 % risk, max 10 contracts, ICs in neutral regime at 3.5 % risk / 12 % combined-credit floor. Full mapping + deviations: `experiments/EXP-503-BT-honest-fills/config.json` `fidelity_notes`.

**Do not quote these numbers as "EXP-503 backtest results"** — they are the fill-model delta on EXP-503's *unwrapped core*. There is no naive baseline to reproduce (first backtest of this core).

## Variants

- **cb40** — engine drawdown breaker at the yaml's `drawdown_cb_pct: 40` (config-faithful). ## Verdict

1. **The core loses money under every configuration and both fill models** — with the yaml's own breaker it rides to the −40 % latch and dies (naive −42.0 %, marketable −40.2 %); without the breaker it is ruined in 2022. Honest fills don't rescue it and don't create it: ~23 % of naive entries were never fillable, and per-trade quality degrades (win rate −2.6 pp nocb, −11.8 pp cb40) once entries must be marketable — same direction as the EXP-800-BT finding.
2. **This does not measure the deployed EXP-503**, whose ML overlay (0.10× bear/high-vol multipliers, crash = no trades, regime-gated signal suppression) exists precisely to cut the exposure that ruins this core. Whether the overlay actually rescues it is **unknowable offline** — the ML path has no backtest integration, which is itself the finding: the model holding a live paper account (−5.2 % broker-verified, plus the −800-share orphan short) is validated by *nothing*.
3. Fleet-picture consistency: the paper account's −5.2 % live return sits between "core is deeply negative" and "backtest claims never existed." Nothing here supports continuing EXP-503; if the family is ever revisited, the blocker list starts with wiring `ml_enhanced` into the backtester end-to-end (or retiring the overlay).
